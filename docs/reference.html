01The question

What the study asks and what would count as an answer.

AlphaGenome predicts hundreds of genomic assay tracks from up to 1,048,576 bp of DNA. It is accurate, and opaque. The project trains sparse autoencoders on its internal activations to decompose those activations into a dictionary of sparse, ideally monosemantic features, then asks two questions of each feature.

  • What does it correspond to? Each feature is matched against ENCODE's registry of candidate cis-regulatory elements and against annotations derived from GENCODE, giving a per-concept AUROC against a permutation null and a raw-channel baseline.
  • Is it causal? Features that match a concept get ablated, and the change in the model's own predictions says whether the feature carries the concept or merely travels with it. This arm is designed but not yet run.

Three hypotheses shape the tap selection and the concept panel.

IDClaimHow it is tested
H1Short sequence motifs are built by convolution and need no attention.Splice donor and acceptor sites should be recoverable at the conv taps, with a flat depth curve.
H2Long-range positional context is built by the transformer tower.Distance to the nearest TSS is unavailable inside a 34 bp receptive field but available inside 1 Mb. Its depth curve should rise across the conv/tower boundary.
H3Regulatory element classes separate by something other than accessibility.pELS and dELS come from the same experimental signal and differ only in TSS distance. If their curves separate, that separation is about position and nothing else.
Voided prior workEvery earlier run, pilot and result of this project was discarded on the user's instruction on 2026-09-13 because of technical errors in that work. No number from it is cited here or used as a design constraint. Architecture facts survived only because they were re-verified by reading the installed port's source directly.

02Model and port

Which AlphaGenome, obtained how, and why PyTorch rather than JAX.

AlphaGenome's weights have been open since 2026-01-28 under non-commercial model terms. Two code paths exist: the official JAX implementation from Google DeepMind, and a community PyTorch port. This project uses the port.

Where the weights and code come from

ArtefactSourceNote
Weightsgtca/alphagenome_pytorchHugging Face. model_fold_0..3.safetensors plus model_all_folds, 920 MB each, converted from the official JAX checkpoint.
Model codegenomicsxai/alphagenome-pytorchGitHub. Requires Python ≥ 3.12. Supplies from_pretrained, DtypePolicy and utils.sequence.
Not thisalphagenome-pytorchThe PyPI package (0.2.4, lucidrains) is the architecture only. It has no from_pretrained, no safetensors loader. Installing it instead of the fork is the easy mistake.

Why the port and not JAX

The whole study depends on reading intermediate activations, and PyTorch hooks make that a two-line operation where Haiku would require rewriting the forward pass to sow intermediates. The fidelity of the port against JAX outputs was audited in an earlier study and is treated as settled here.

Verified architecture

Read from the loaded model, not from documentation. 450.5M parameters.

The hook recipe, and why a naive hook failstower.blocks[i] is an nn.ModuleDict with no forward. A plain register_forward_hook on it never fires, and never warns. The residual adds live in TransformerTower._forward_block, a plain Python method, so the residual stream is not any module's output. It is mha's input, captured with register_forward_pre_hook(fn, with_kwargs=True).

Each block is a ModuleDict of pair_update, attn_bias, mha, mlp. An older note claimed pair_update exists only on even blocks; that is wrong for this checkpoint, where all nine blocks carry it.

One more orientation point: embeddings_128bp is head-adjacent, not internal. It is the last shared representation before the prediction heads, the opposite end of the network from the early conv layers the reference study taps.

03Taps

Six read points spanning depth, and the reasoning behind each.

A "tap" is a place in the network where activations are captured. The study needs several, because the central question is where a concept is built, and that is only visible as the shape of a curve across depth.

TapKindbin (bp)channelsWhat it can see
bin_size_4encoder41024A short receptive field. Motif scale.
bin_size_16encoder161280Motif plus immediate flank.
bin_size_64encoder641536Last conv stage before the tower.
resid_pre_b0tower1281536Entering attention, nothing added yet.
resid_pre_b4tower1281536Mid-tower.
resid_pre_b8tower1281536Last block. Full 1 Mb context available.

The reference study, Learning monosemantic features in multitask DNA regulatory sequence models via sparse autoencoder decomposition (calico/sae-borzoi), taps Borzoi's conv1d_1 through conv1d_4, with receptive fields of 14 to 34 bp. Those are all convolutional. This project keeps three comparable conv taps and adds three tower taps, because the conv-only design cannot answer H2 at all.

The confound this design controlsDictionary width and row budget are held equal across taps: H = 8192 features and roughly 8.2M training rows everywhere. If the deeper tap had a bigger dictionary or more data, a rising depth curve would be uninterpretable. See §15 for the way this guarantee partly failed in practice.

04Train/test separation

Published folds, and the context margin that a naive split gets wrong.

Claims of the form "the SAE found this on data the backbone never saw" require knowing exactly what the backbone saw. The split is therefore taken from the published fold definition, not invented.

Source

Borzoi's sequences_human.bed.gz: 55,497 regions of 196,608 bp, labelled with 8 folds. SHA-256 13724966c9378c2fd024c62e6bb72b94850e12d96d23a419f60040ae50b98ba3

Those pairs are disjoint by construction. No region is held out by more than one model, so there is no common test set and each model fold is evaluated on its own territory. This was also verified empirically: zero overlap between the three folds' held-out windows.

The context guardA training example predicts 196,608 bp but reads 1,048,576 bp. Anything inside that wider span was seen, even if no loss was computed on it. Training regions are therefore widened by a margin of 425,984 bp on each side before being subtracted from the held-out territory. Skipping this is the quiet way to leak the backbone's training data into a held-out claim.

05Window manifests

What gets read, in what split, with gaps excluded.

Each fold gets 1,600 windows of 1,048,576 bp across 23 chromosomes, drawn without replacement in a fixed random order.

SplitWindowsTerritoryPurpose

dev100unseenThe only split tuning may look at.

Assembly gaps

GRCh38 models centromeres and telomeres as long runs of N. A scan of the primary assembly with a 1,000 bp minimum found 366 gaps totalling 151.0 Mb, of which 150.6 Mb sit on chr1–22, X and Y. Those regions are subtracted from both territories before tiling.

Verified: 0 of 4,800 windows overlap a gap; without the exclusion, one would have. Shorter N runs survive and are handled at the bin level instead — a sampled check found ambiguous bases in 2 of 100 windows, costing exactly 1 row in 1,310,719 during a pilot, so the equal-row-budget claim holds to a rounding error.

That gap file is reused as a landmark source: the widest gap on a chromosome is its centromere, which is what the browser figure's ideogram draws.

The step budget is ours, not the reference'sThe vendored repository contains the model class, not a training loop, so no published step count exists. 6000 was chosen from a measured pilot: on one tap at 1/12.5 scale, validation FVU was 1.01 at step 100, 0.41 at 1000, and 0.234 at 3000 and still falling about 3% per 100 steps. The budget is part of the recipe and the recipe is part of the resume identity, so it cannot be raised after the fact — changing it means retraining from scratch, and all three folds must share it to stay comparable.

AuxK, the standard remedy for dead latents, is deliberately not in the recipe. If used, it enters as a separately labelled arm, never as an edit to the vendored core.

08Extraction

One forward pass, six taps, measured cost.

ag_sae/extract.py installs all hooks once, runs each window through model.encode a single time, and captures every tap from that one pass. Positions are sampled randomly rather than on a stride, because a stride can align with periodic features and the SAE sees rows independently anyway.

Storage is float16. That is safe with room to spare: the largest absolute activation measured on real shards was about 167, against float16's ceiling of 65,504. Extraction refuses to write a shard containing a non-finite value, so an overflow would fail loudly rather than silently.

Resumability

index.json is rewritten after every shard and records the shards already done, guarded by an identity check on the manifest and settings. On a spot preemption the run resumes from the last finished shard, costing at most 8 windows.

Timing, correctedAn early estimate of 7.75 s per window, taken from a 16-window trial, predicted 3.5 h per fold. The real figure at full scale was 9.75 h, about 2.8× the estimate. Budget roughly 19 h per fold end to end, or 57 h for three.

09Training

Step-budgeted, identity-checked, exactly resumable.

ag_sae/train.py trains one SAE on one tap of one fold. Per fold that is 6 taps × 3 seeds = 18 runs; across three folds, 54. Three seeds because sparse autoencoders depend on initialisation, and a feature found by one seed may be that seed's artefact.

Scales are computed from the training split only; using validation would leak its distribution into the model. Checkpointing is every 100 steps, and the best checkpoint is kept by validation FVU.

Resume identity

A resume is refused unless everything matches: the recipe, hashes of the training and validation shard sets, the torch and numpy versions, the device type, and the SHA-256 of train.py, sae.py and the vendored core. Two consequences worth internalising:

  • Editing any of those source files mid-campaign makes every in-progress run refuse to resume. That is the intended behaviour — loud, not silent.
  • run_fold.sh is read incrementally by bash while it runs, so editing it during a run can corrupt execution. Leave it alone until the fold finishes.

Two checkpoint files are written per run. latest.pt carries Adam state for resuming, around 300 MB, and is excluded from the Drive archive. best.pt carries only what analysis needs and is the file that gets archived and loaded by the matcher.

10Concept matching

Frozen SAE in, per-concept AUROC out, against a null that respects the genome's structure.

ag_sae/concepts.py is deliberately decoupled from training. Concept matching must never reach checkpoint selection, or the independence claim collapses.

AUROC under extreme sparsity

Under TopK most bins score exactly zero, so ties are the common case, not an edge case. Ties get half credit, as the Mann-Whitney definition requires. Ignoring them gives the wrong answer for almost every feature.

a = number of positive bins that fire
wins = a·(negative zeros) + 0.5·(positive zeros)·(negative zeros)
     + rank sum over firing positives − a(a+1)/2
AUROC = wins / (n_pos · n_neg)

Ranks are invariant under label permutation, so they are computed once and reused across permutations. That took the null calibration from 27 minutes to 24 seconds at 1 Mb scale.

The null

Labels are circularly shifted within contiguous runs of bins, and the statistic taken is the maximum over the dictionary. Two properties matter:

  • Shifting inside runs preserves each concept's spatial clustering. Adjacent bins are strongly correlated; a null that destroys that structure is far too permissive.
  • Taking the max over the dictionary in the null matches the max taken in the observed statistic, so the multiplicity of searching 8192 features is absorbed rather than ignored.
Grid trap, now guardedRuns are found by comparing the gap between bins to bin_bp. Matching a conv tap (4, 16 or 64 bp bins) with the old 128 bp default made every bin its own run, the shift became the identity, the null equalled the observed statistic, and nothing was ever called recovered — silently. The bin width is now read from the coordinates file and a mismatched explicit value raises.

Scale note

In a single 1 Mb region, PLS has roughly 12 elements, which pushes the null ceiling to about 0.62. Locus-level inspection works at that size; AUROC statistics do not. Matching runs on the full test split, not one window.

11Statistics

What each question needs, what the data cannot support, and what not to use.

QuestionMethod
Is the concept recovered at this tap?The circular-shift permutation test above. Already the right instrument; nothing to add.
Does the SAE beat raw channels?Needs both sides calibrated against their own null. See the flag below.
Does the tower add anything?Bootstrap over windows, not bins, within each fold. Consistency of direction across folds as a pre-declared criterion.
Do seeds agree?Descriptive. Best cosine match between dictionaries, against a random-direction null.
Is a feature causal?Paired permutation on ablation differences, clustered by window, with FDR across features — and a frequency- and magnitude-matched random-feature control.
Both sides are now calibrated — fixed 2026-09-14The null used to be computed only on the SAE codes, so sae_minus_raw compared a maximum over 8192 features against a maximum over 2 × d_in channels. The raw baseline now gets the same circular shifts, and the reported quantity is each side's excess over its own ceiling.

The direction of the old bias turned out not to be predictable, which is itself the argument for measuring rather than reasoning. Two forces pull the ceilings apart and they oppose each other: more candidates raise a maximum even under pure noise, while TopK sparsity ties most bins at zero and narrows the spread the maximum is drawn from. On a real checkpoint the SAE ceiling came out lower than the raw ceiling, the opposite of the naive expectation.

A second mismatch found in the same placeThe observed statistic folded AUROC onto [0.5, 1] and picked only from features that fire; the null did neither, taking a plain maximum over all features including dead ones. The null was therefore systematically too low and "recovered" too easy. Measured on a real checkpoint, correcting it moved the PLS ceiling from 0.661 to 0.698 and the dELS ceiling from 0.576 to 0.597. Null and observed now run through the identical statistic.
What three folds cannot doA sign test with n = 3 has a one-sided floor of p = 0.125. No fold-level result can be "significant" no matter how clean it is. Fold agreement is qualitative replication and must be reported as such. Seeds are not biological replicates either — they measure optimisation noise, so take a median within fold and show the spread as a robustness band.

Multiplicity. 6 taps × 11 concepts × 3 folds is roughly 200 primary comparisons. Benjamini–Hochberg is appropriate, with the family declared in advance; controls are diagnostics and do not join the family. At q = 0.05 over 200 tests the smallest threshold is about 2.5 × 10⁻⁴, which 200 permutations cannot resolve — the floor is around 0.005. Either raise permutations into the thousands, or fit an extreme-value tail to the permutation maxima, which is standard for max-statistics and far cheaper.

A hierarchical Bayesian layer is a reasonable addition for the aggregate questions, not a replacement for the permutation test. It handles the n = 3 problem coherently, separates seed variance from fold variance explicitly, and its shrinkage does the multiplicity work that BH does by thresholding. Priors would need freezing alongside the panel. Do not attempt a bin-level Bayesian model: millions of autocorrelated bins would need a spatial Gaussian process, which is a separate research project.

Not to be used: chi-square or Fisher on bin counts, t-tests across bins, bin-level Pearson correlation, binomial tests on overlap counts. All assume independent bins. Neighbouring bins are strongly correlated and these inflate significance badly. This is the single most common statistical error in this corner of genomics. Note the nuance: Fisher is not wrong in general — on discrete, well-separated units such as seqlets or motif hits it is perfectly defensible, and the reference study's own code contains no Fisher test at all, delegating motif statistics to MEME E-values and TOMTOM, with a bedtools-based control for seqlet overlaps.

12Figures and tracks

Nine publication figures, plus the same numbers in browser formats.

Every figure writes PDF, SVG, 300 dpi PNG and a CSV of the numbers behind it. The CSV is required rather than convenient: three palette slots fall below 3:1 contrast on white, and the rule is that colour always ships with a table view. SVG keeps text as text and PDF uses Type 42 fonts, so both open editable in Illustrator.

FigureQuestion it answers

Why the feature card has two logosShowing only the strongest sites makes any feature look monosemantic. The second logo samples the firing range evenly. If the two disagree, the feature is not monosemantic no matter how clean its top examples look. This is the interpretability illusion, and the figure exists to expose it.

Logos are drawn with logomaker, in the project's validated base colours, with stack_order="big_on_top" — readers take the top letter of a stack as the consensus, so inverting the order inverts the reading.

ag_sae/tracks.py writes activations as bedGraph and intervals as BED, plus an igv.js session dictionary. IGV desktop, igv-notebook and UCSC all read those. The viewer is never a dependency: tracks.show imports igv-notebook lazily. bedGraph rather than BigWig because BigWig needs a compiled writer and one value per 128 bp bin is small enough as text; zero rows are dropped because under TopK most bins are exactly zero.

Archiving

Activations go to Google Drive rather than being deleted. Measured upload is 139 MB/s, so a 219 GB fold takes about 27 minutes, and rclone check verifies against Drive's MD5. Nothing is deleted that has not verified. After verification only train, val and test_trained shards are removed; test and dev stay on disk so concept matching does not require pulling 219 GB back. Peak disk under that policy is about 304 GB of 381 GB during fold 2.

Two cautions. Drive enforces a 750 GB/day upload cap, and three folds total roughly 657 GB — a 57 h campaign spans more than a day, so it should not bite, but a re-upload could. And GCE-to-Drive traffic may be billed as internet egress at roughly $0.12/GB, which would be around $79 for three folds; this is unverified and worth checking on the billing console after the first fold. A same-region Cloud Storage bucket would avoid both and cost far less.

Operational gotchapkill -f tensorboard inside a gcloud compute ssh --command string matches the SSH command's own process and kills the session before anything after it runs. Use pkill -f "[t]ensorboard".

15Open problems

Known, unresolved, and consequential.

Dead latents break the equal-dictionary guarantee

The design holds H = 8192 constant across taps so that the depth comparison is not confounded by dictionary size. The nominal width is constant. The effective width is not, and it varies along exactly the axis under comparison:

TapDeadEffective dictionary
bin_size_64~470~7,720
bin_size_16~1,160~7,030
bin_size_4~1,920~6,270
resid_pre_b0~2,560~5,630
resid_pre_b4~4,850~3,340

A 2.3× spread. The mitigating fact is that the best-of-dictionary null takes its maximum over the same effective dictionary, so calibrated AUROC comparisons remain fair. What does not survive is the sentence "we learned a dictionary of 8192 features": at resid_pre_b4 roughly 3,340 were learned. AuxK is the standard remedy and is already planned as a separate labelled arm.

Permutation resolution

200 permutations cannot support FDR correction across roughly 200 comparisons. Raise the count or fit an extreme-value tail.

Not yet built

  • The ablation arm. Designed in outline only; the matched random-feature control is the load-bearing piece.
  • Motif analysis. The reference study's MEME and TOMTOM path has no counterpart here yet.
  • Folds 1 and 2.
